# 使用手册（Usage Guide）

界面一共 **5 个 Tab**：`登录` / `自动抢课` / `搜索抢课` / `全部课程` / `已选课程 / 进度`。
顶部一行是全局状态（任务进度）+ 运行日志框，最下面一行写着日志文件路径（点「打开日志文件夹」直接跳过去）。

> 通用前提：**每次重启软件都要重新点一次「抓取 Cookie」**。教务 Cookie 不落盘，这是设计如此。

---

## 1. 登录 Tab

| 控件 | 作用 |
|---|---|
| **服务器地址** | 默认 `https://jwxt.zjgsu.edu.cn/jwglxt/`。只接受该域名下的 https 地址（换别的会被拒绝） |
| **打开登录窗口** | 启动一个**独立**的 Edge 实例（独立用户目录 + 调试端口 9227），与你的日常浏览器互不干扰 |
| **自动抓取 Cookie** | 从那个独立 Edge 读取教务 Cookie（走 CDP），成功后就能查询 / 提交 |
| **验证 Cookie** | 用当前 Cookie 试登录一次，确认还有效 |
| **复制 Cookie 给外部软件** | 把 Cookie 串复制到剪贴板（喂给别的工具用） |
| **关闭登录窗口 / 调试端口** | 关掉独立 Edge，释放端口；**已抓到的 Cookie 不受影响** |
| **打开日志文件夹** | 打开 `%LOCALAPPDATA%\工商大学选课助手\logs\` |

**推荐顺序**：打开登录窗口 → 在弹出的 Edge 里登录教务 → 自动抓取 Cookie → 验证 Cookie → （可选）关闭登录窗口。

## 2. 全部课程 Tab

- **「拉取全部课程」**：并发拉取全校教学班（实测约 2700 门 / 13 秒），结果落本地缓存 `course_catalog.json`。
  之后搜索可以完全离线跑（界面会注明「本地搜索」）。
- 表格带**校区**列：非你所在校区（教工路）的行整行标红 + `⚠`。
- **「导出 Excel」**：导出当前列表，位置由你在系统对话框里选（不会偷偷写桌面）。

> 缓存是抢课当天的「库存快照」。教务名额变化很快，真正决定成败的是提交那一刻的教务返回；
> 缓存主要用来离线挑课、看容量与教师。

## 3. 搜索抢课 Tab

### 顶部搜索行
- **关键字输入框** + **模式**：`教学班`（锁定具体某班）或 `课程名`（按课程名抢，服务端取第一个班）
- **「搜索」**：有 Cookie 走在线查询，无 Cookie/勾了缓存则走本地缓存（状态行会写明）

### 筛选区（点击标签，可多选）

| 条件 | 语义 |
|---|---|
| **上课节次** | 按第几节过滤（可多选） |
| **周数筛选** | 两个模式：**只留含于**（默认，课的周次全部落在你输入区间内）／**剔除重叠**（去掉与区间有任何重叠周次的课）。输入支持 `1-7`、`8-13`、`1-7,14-16`、带 `(单)`/`(双)`；输入后回车生效，点「清空」去掉条件 |
| **学分筛选** | 按钮按你课程数据里**实际出现过的学分**动态生成，通识课常见 1 分 / 2 分；可多选 |
| **上课校区** | `全部 / 下沙 / 教工路`，**默认下沙**（非本校校区默认过滤掉） |
| **▸ 更多筛选（课程归属 / 课程组）** | 默认收起；里面有启用中的条件时会自动摊开，按钮上写着「已启用 N 项」，避免"看不见的条件把课悄悄筛掉" |

⚠ 所有筛选都是**帮你看**的，不改变提交口径：教务的冲突判定**按节次、不看周次**，
所以「周次不重叠」不等于教务一定放行（实测同节次不同周次仍被判「上课时间冲突」）。
被条件筛掉多少条，状态行都会写明（例如「另有 N 个被『学分=1 分』筛掉（含学分未知的）」），不会让你以为搜索坏了。

### 结果表格与勾选

- 第一列**「选」**是勾选框：点一下勾上／取消，可多选；**勾选的行整行变绿加粗**，一眼能看出来
- 全选入口：工具行 `☑ 全选`、`☐ 清空勾选`、`⇄ 反选`，或表头点「选」，或 `Ctrl+A`
- **「加入勾选到抢课」**：把勾选的行批量加进「自动抢课」的待选列表（每行**锁定各自的教学班**，详情一起写入）
- **「一键抢课（勾选行）」**：批量提交（整批共用一个连接，只登录一次）；勾了「循环抢课」时会在多轮之间反复重试未成功的班
- 一行都没勾时，两个按钮都会退回"当前高亮选中的那一行"

### 页面滚动
搜索行固定在顶部；筛选区 + 抢课区 + 勾选工具行 + 结果表格整体可上下滑动（窗口够高时滚动条自动消失）。
**滚轮归属**：指针在结果表格上、且表格自己还有内容可滚 → 滚表格；否则滚整页；指针在别的 Tab → 各滚各的。

## 4. 自动抢课 Tab（待选 / 志愿）

### 待选列表
| 按钮 | 作用 |
|---|---|
| **添加 / 删除选中 / 清空全部** | 维护志愿列表（清空会写日志留痕） |
| **上移 / 下移** | 调整优先级（顺序影响「优先盯前N门」和保底策略） |
| **刷新人数** | 重新查这些教学班的余量/容量 |
| **导出 Excel** | 导出志愿列表 |
| **预设输入** | 按文本批量导入课程（课程名 / 课程号 / 教学班号） |

第三列就是**抢课实际使用的关键字**：写教学班号＝锁定该班；写课程名＝按名抢（服务端取第一个班，时间列会注明「缓存中同名 N 个教学班」）。

### 自动分配时间段（按已选课表）
点一次就会按「已选课程占用的时间 + 各类别剩余名额」给每条志愿挑教学班：

- 硬约束：不与已选课程撞时间（会挑不撞的那个班）
- 类别还有名额时，前序志愿占用的时间段会保留，同一时段不重复押注
- 名额已够的类别只作保底，不占时段
- 候选之间优先选**还有空位**的教学班

结果写回待选列表并逐条写进日志说明原因（已分配／备用／无可用时间）。
加入课程后、开抢前、启动时、已选课程有变动时都会自动跑一次。
开关「**自动避开时间冲突**」控制是否启用。

### 抢课旋钮

| 旋钮 | 含义 |
|---|---|
| **优先盯前 N 门** | 0 = 盯全部。填 N 后只高频盯列表最前面 N 门，其余**每 3 轮**兜底试一次；前 N 门都到手后自动恢复全量 |
| **满课节流(秒)** | 满课盲打的间隔（默认 2.5，允许 0.5–10）。调小更激进（更容易捡到退课空位），但更可能被教务判「频率过高」 |
| **最多选 N 门** | 抢够 N 门自动停（默认 0 = 不限） |
| **最大轮次** | 跑够 N 轮自动停 |
| **循环抢课** | 在「一键抢课（勾选行）」与监控里反复重试未成功的班 |
| **定时开始** | 填 `HH:MM` 或 `HH:MM:SS`（如 `09:59:58`），到点自动开抢 |
| **开始监控 / 停止** | 启动/停止抢课循环 |

### 抢课循环什么时候会停（收工条件）

1. 你点「停止」
2. 达到「最大轮次」
3. 达到「最多选 N 门」
4. 目标全部完成
5. **没得抢了**：全量志愿里没有任何一门值得提交（名额满 / 已完成 / 与教务已选重复）→ **直接收工，一次请求都不发**，日志写明原因。以前这种情况会空转一整晚（实测 48 秒刷 110 轮），现在会自己停

⚠ 收工 = 这一轮没有可提交的志愿了。如果之后教务**掉课**（志愿没中 / 被退），已选刷新会把课放回待选，此时需要**重新点一次「开始监控」**（不会自动接上）。

### 日志怎么看（抢课当天最有用）

启动时会写一行**名额基数**，事后一眼看出当时是不是已经没名额：

```
类别名额基数（教务已选 + 本程序抢到）：通识 2/2，英语 1/1，体育 1/1
```

- 满课蹲守：日志会写「教务名额标记」，说明这轮是被满课挡住的（会继续重试，不是失败）
- 时间冲突这类硬失败：继续重试
- 没有名额上限的志愿（如主修课）：通识满了照样抢
- 首次出现的异常返回会**把原始返回落盘留档**，方便反馈问题

## 5. 已选课程 / 进度 Tab

- **「自动对齐已选（每60秒）」**：开关一个只读的定时查询——每 60 秒问一次教务「我到底选上了哪些」，
  和本程序的记录对账：抢到就记账、掉课就放回待选。**与抢课循环相互独立**，不想让它每分钟查一次就关掉。
- 界面会显示 `已选数据：HH:MM:SS（自动对齐中，每 60 秒）`；**缺 Cookie 时它会明说**
  （`尚未刷新（自动对齐中·缺 Cookie，点一下「抓取 Cookie」就开始…）`），不再闷声不响。
- **进度卡口径**：英语 / 体育 / 通识的已选数 = **教务已选 ∪ 本程序抢到** 的并集
  （不是只算本程序抢到的），开抢时传给循环的名额上限也用这套真值。
- **「刷新已选课程」**：手动拉一次教务已选。

## 6. 抢课当天的建议流程

| 时间 | 动作 |
|---|---|
| 抢课前 1 天 | 装好环境、跑一遍登录 + 拉取全部课程，把想抢的课加进待选、排好顺序、点一次「自动分配时间段」 |
| 抢课前 10 分钟 | 重新抓 Cookie → 验证 Cookie → 「刷新已选课程」→ 看进度卡确认名额基数 |
| 抢课前 1 分钟 | 设好「优先盯前N门」「满课节流(秒)」，用「定时开始」填开抢时刻（如 `09:59:58`） |
| 开抢 | 程序按顺序提交；满课就按节流间隔盲打，直到捡到退课空位 |
| 抢完 | 看日志确认结果 → 「刷新已选课程」核对 → 关掉不需要的开关（如「自动对齐已选」） |

## 7. FAQ

**Q：以前抢到的课，教务里掉课了怎么办？**
A：日志会显示对账结果（例如「已从教务已选消失，放回待选列表」），待选列表里会重新出现，**需要你重新点「开始监控」**。

**Q：为什么「已选课程」里同一门课看起来像两条？**
A：v0.1.9 已修。判重按**核心教学班号**（学期+课程号+班号），忽略校区/网课平台/课程别名前缀。

**Q：几门课同一个课程号，能都押吗？**
A：不。同一门课只允许第一条成为「已分配」，其余自动降为「备用」并在日志写明原因 ——
因为教务对同一课程选两个班通常是把先选上的**替换掉**（等于白扔一次机会）。这条跨重启也有效。

**Q：搜索结果里的课点了没用？**
A：先确认「上课校区」筛选是不是把教工路滤掉了（默认下沙），以及「更多筛选」里有没有启用中的条件。

**Q：日志文件多大？**
A：`logs/app.log` 超过约 1 MB 会轮转（每片 256 KB 量级），不会无限增长。
